# 云妆 AI 知识助手 · 演示交付说明

## 1. 交付范围

本仓库在 `codex/yunzhuang-demo` 分支提供一个**本地可运行**的云妆演示切片：

- Python 3 标准库实现的 JSON API（`http.server`），不依赖第三方包；
- 中文单页医生工作台 / 品牌管理员工作台（`index.html`，内联 CSS/JS，无外部资源）；
- 虚构医生、患者、品牌知识与会话数据（`mock_data.json`）；
- 权限隔离、引用、拒答、版本过滤、确认归档与幂等同步的回归测试（`test_app.py`）。

**不在本次范围**：生产部署、真实模型调用、WeKnora/原后台/小程序/微信集成、真实患者或医疗数据、生产级登录鉴权与持久化。

> 全部业务数据均为虚构演示数据，仅用于功能演示，不构成医疗建议或真实服务承诺。

## 2. 文件清单

| 文件 | 作用 |
|---|---|
| `app.py` | 标准库 HTTP 服务、路由、身份校验、问答检索、权限、归档与幂等逻辑 |
| `mock_data.json` | 虚构医生 D001/D002、患者 P001/P002/P003、品牌知识版本与模拟会话 |
| `index.html` | 中文单页 UI：医生问答、患者切换、引用/事实侧栏、补录确认、管理员只读与品牌知识维护 |
| `test_app.py` | 11 项端到端 HTTP 回归测试（`unittest`） |
| `docs/交付说明.md` | 本文件 |

## 3. 本地运行

要求：Python 3.10+（当前验证环境 Python 3.12.15），无需安装依赖。

```bash
cd yunzhuang-demo
python3 app.py
# 浏览器访问 http://127.0.0.1:8000/
```

可选参数：

```bash
python3 app.py --host 0.0.0.0 --port 8080 --verbose
```

首次打开页面会弹出“选择模拟身份”，三选一进入。也可通过接口头 `X-Demo-Session` 直接调用 API。

## 4. 模拟身份与患者归属

| 身份 | 模拟会话头 | 可访问患者 | 权限 |
|---|---|---|---|
| 医生张然 D001 | `demo-doctor-d001` | P001、P002 | 问答、补录、确认归档、同步来源记录 |
| 医生李澄 D002 | `demo-doctor-d002` | P003 | 同上，仅本人患者 |
| 品牌管理员王宁 A001 | `demo-admin-a001` | 全部患者只读 | 品牌知识版本维护；患者写操作 403 |

- 身份只由 `X-Demo-Session` 决定。请求参数或请求体中的 `doctor_id` 一律忽略。
- 缺少或无效会话头返回 `401 UNAUTHORIZED`。
- 未选择患者时只能进行品牌通用问答；患者个人问题返回拒答，不检索患者事实。
- 切换患者时，服务端清空该会话既有消息，只保留新患者上下文。

## 5. API 一览

所有接口前缀为 `/api/v1`，错误统一返回：

```json
{"error": {"code": "FORBIDDEN", "message": "无权限说明"}}
```

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/health` | 健康检查与模拟数据声明 | 公开 |
| GET | `/me` | 当前模拟身份 | 已登录 |
| GET | `/session` | 当前患者、会话范围与消息 | 医生 / 管理员 |
| GET | `/patients` | 医生本人患者；管理员返回全部患者 | 已登录 |
| POST | `/sessions/patient` | 选择/切换患者，清空旧会话 | 医生本人患者 |
| DELETE | `/sessions/patient` | 清空患者上下文，回到品牌问答 | 医生 |
| POST | `/qa` | 检索并回答，返回引用编号与版本 | 医生；管理员仅品牌问答 |
| GET | `/patients/{pid}/facts` | 患者已归档事实 | 医生本人 / 管理员只读 |
| GET | `/patients/{pid}/candidates` | 患者补录候选 | 医生本人 / 管理员只读 |
| POST | `/patients/{pid}/candidates` | 创建补录候选（待确认） | 医生本人 |
| POST | `/patients/{pid}/candidates/{cid}/confirm` | 确认候选并归档为患者事实 | 医生本人 |
| POST | `/patients/{pid}/sync-records` | 模拟外部来源记录同步 | 医生本人 |
| GET | `/brand/knowledge` | 有效品牌版本；管理员可带 `include_inactive=1` | 已登录 |
| POST | `/brand/knowledge` | 新增品牌知识版本 | 品牌管理员 |
| PATCH | `/brand/knowledge/{source_id}/{version}` | 启用/停用品牌版本 | 品牌管理员 |

## 6. 关键业务规则

### 6.1 归属隔离

- 医生只能访问 `patient.doctor_id == actor.actor_id` 的患者；跨医生读写均返回 `403 PATIENT_FORBIDDEN`。
- 管理员读取患者资料与事实仅供查看；补录、确认、同步、进入患者会话均返回 403。
- 问答检索前重新校验当前会话患者归属，避免会话期间切换造成越权。

### 6.2 回答与引用

- 未选患者：仅检索 `status=active` 的品牌知识。
- 已选患者：检索有效品牌知识 + 该患者已归档事实，最多引用 3 条。
- 回答中的 `来源N` 与 `citations[].no` 一一对应；每条引用包含 `source_id`、`version`、`title`、`scope`、`quote`。
- 没有命中有效资料时返回 `answered=false`、`reason=NO_EVIDENCE`、`citations=[]`，明确说明不能回答。
- 未选患者但提问包含患者 ID、过敏史、护理记录等个人上下文时，返回 `reason=PATIENT_CONTEXT_REQUIRED`，不会返回患者事实。

### 6.3 补录归档

- 候选由所属医生创建，初始状态为 `pending`。
- 只有所属医生确认后，候选才变为 `archived` 并生成患者事实：`origin=local_supplement`。
- 重复确认返回 `already_archived=true`，不会重复生成事实。
- 本地补录与外部来源记录分开存储；确认候选不写入 `source_records`。

### 6.4 版本与幂等

- 品牌知识按 `source_id + version` 幂等新增：重复提交返回 `duplicate=true`，不重复写入。
- 同一 `source_id` 新增有效版本时，旧的有效版本自动变为 `retired`。
- 问答仅检索 `status=active` 的版本；医生列表不返回停用版本。
- 患者外部来源记录按 `patient_id + source_id + version` 幂等；重复同步返回 `duplicate=true`，不重复生成事实。

## 7. 测试与验证

执行：

```bash
python3 -m unittest -v
```

当前结果：**11 项测试全部通过（OK）**，覆盖：

1. 缺少/无效会话头 401，身份只认会话头，伪造 `doctor_id` 无效；
2. 跨医生读取、补录、同步患者均 403；
3. 管理员读取患者资料成功，补录/确认/同步/进入会话均 403；
4. 未选患者仅返回品牌知识，个人问题拒答且不含患者事实；
5. 切换患者清空旧会话，旧患者事实不进入新上下文；
6. 回答附来源编号与版本；无依据问题明确拒答；
7. 停用品牌版本不参与检索，管理员可查看停用版本；
8. 补录候选确认归档，重复确认幂等；
9. 来源 ID + 版本同步幂等，不同版本分别归档；
10. 管理员新增品牌版本幂等，旧有效版本自动停用；
11. 单页 UI 可访问并明确标注模拟数据。

同时执行 `python3 -m py_compile app.py`、`node --check`（前端脚本）与 `git diff --check`，均应通过。

## 8. 真实限制

- 服务状态全部在内存中，重启后恢复 `mock_data.json`，不提供数据库或持久化。
- `X-Demo-Session` 是演示用身份选择，不是安全认证；任何能访问服务的调用方都可选择模拟身份。
- 检索使用人工维护的关键词命中与固定排序，不包含向量检索、真实大模型或真实医学知识库。
- 未接入原后台、小程序、微信、WeKnora 或任何真实患者数据；不执行生产部署。
- 管理员品牌知识维护与患者只读约束是演示行为，未实现审批、审计日志、并发版本控制或权限中心。
- 本仓库未推送远端、未创建 MR；由操作者通过已授权的 GitHub 连接发布相同文件并创建 PR。
